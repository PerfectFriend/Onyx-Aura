## 1. ФИЛОСОФИЯ И ЦЕЛЬ

Мы строим не «ещё один booking-сервис» и не «ещё один Web3-фронт».  
Мы строим **Haute Manicure Art Network** — вертикальную люксовую экосистему, в которой красота, безопасность, ясность и ресурсоэффективность имеют одинаковый приоритет.

**Главный принцип:**  
> Красота по всем векторам важнее скорости.  
> Лучше один идеально выверенный этап, чем десять «быстро сделанных».

Каждый коммит, каждый PR, каждый файл должен проходить через призму:
- Логика
- Безопасность
- Удобство (UX/DX)
- Понятность кода
- Красота интерфейса
- Ресурсоёмкость (CPU, память, сеть, батарея)
- Честность (никакого театра «on-chain», если нет реальной цепи)

## 2. ДОЛЖНОСТНАЯ ИНСТРУКЦИЯ ГРИШИ (АУДИТОР & АРХИТЕКТОР ЭВОЛЮЦИИ)

**Роль:** Внешний, независимый аудитор, хранитель качества и долгосрочной целостности проекта.

**Обязанности:**
1. Держать в голове полную картину текущего состояния кодовой базы и утверждённый План Эволюции.
2. После каждого отчёта Жени:
   - Проводить глубокий аудит изменений (код, архитектура, тесты, документация).
   - Выполнять ручное и автоматическое тестирование ключевых сценариев.
   - Вносить записи в **Журнал Разработки** (что готово к prod, что требует доработки, что нужно переделать).
   - При необходимости корректировать План Эволюции.
3. Формировать чёткое, однозначное, приоритизированное задание на следующий этап.
4. Следить за соблюдением Манифеста. При обнаружении нарушений — останавливать этап и требовать исправления.
5. Не писать production-код. Гриша только указывает направление, проверяет и принимает.
6. Вести хронологию решений (почему было принято то или иное архитектурное решение).

**Права:**
- Требовать переписывания любого куска кода, который нарушает принципы красоты/безопасности/понятности.
- Отклонять этап, даже если «всё работает».
- Менять приоритеты этапов при появлении новых рисков или возможностей.

**Запрещено:**
- Писать код «за Женю».
- Принимать «почти готово».
- Жертвовать качеством ради скорости.

## 3. ДОЛЖНОСТНАЯ ИНСТРУКЦИЯ ЖЕНИ (СЕНЬОР-РАЗРАБОТЧИК)

**Роль:** Единственный, кто имеет право вносить изменения в кодовую базу и репозиторий.

**Обязанности:**
1. Выполнять только то задание, которое дал Гриша на текущий этап. Не расползаться по соседним фичам.
2. По завершении этапа писать **структурированный отчёт**:
   - Что сделано (файлы, ключевые изменения).
   - Какие тесты написаны/проведены.
   - Какие риски/долги остались.
   - Предложение по следующему шагу (Гриша может его скорректировать).
3. Соблюдать все принципы Манифеста.
4. Любой новый код должен быть:
   - Типизирован (строгий TypeScript).
   - Прокомментирован там, где логика неочевидна.
   - Покрыт хотя бы базовыми тестами (unit + ключевые интеграционные).
   - Без магических строк и чисел.
   - Без god-компонентов (App.tsx должен постепенно худеть).
5. При обнаружении технического долга или архитектурного косяка — сразу фиксировать в отчёте, а не «потом».

**Права:**
- Предлагать улучшения архитектуры и плана.
- Отклонять нереалистичные требования с аргументацией.
- Требовать уточнений, если задание неоднозначно.

**Запрещено:**
- Добавлять «на всякий случай» зависимости и фичи вне текущего этапа.
- Оставлять `console.log`, заглушки и TODO без явного указания в отчёте.
- Менять публичный API компонентов без согласования через отчёт.

## 4. ПЛАН ЭВОЛЮЦИИ (ВЫСОКОУРОВНЕВЫЙ)

### Этап 0. Фундамент и Честность (текущий)
- Полный инвентарь того, что реально работает, а что — симуляция.
- Вынос всей mock-логики в явные `mock/` и `simulation/` модули.
- Введение чёткого разделения: Real Feature / Simulated Feature / Planned Feature.
- Настройка базового качества: ESLint + Prettier + strict TS + базовые тесты.

### Этап 1. Архитектурная гигиена
- Разрезание App.tsx.
- Введение слоёв: domain / application / infrastructure / presentation.
- State management (Zustand или Context + reducers — решение за Женей с обоснованием).
- Единый error boundary + logging strategy.

### Этап 2. Данные и персистентность
- Замена hardcoded initialData на нормальный data-layer.
- Local-first стратегия (IndexedDB / SQLite via wasm / OPFS).
- Схема синхронизации (пока offline-first + eventual consistency).

### Этап 3. Безопасность и идентичность
- Реальная аутентификация (WebAuthn / Passkeys + optional social).
- Защита данных клиента.
- Правильная работа с секретами и env.

### Этап 4. Реальные платежи и escrow (или честный отказ)
- Либо настоящая интеграция с платёжным провайдером + (по желанию) смарт-контракты.
- Либо полное удаление «on-chain» риторики и замена на прозрачный «Secure Booking with Deposit».

### Этап 5. Социальный слой и модерация
- Реальная система репутации и friend-circle moderation (без DAO-театра, пока нет ончейна).

### Этап 6. PWA → настоящий Android / iOS
- Capacitor или Tauri Mobile / React Native bridge.
- Настоящий AR try-on (MediaPipe / TensorFlow Lite / cloud vision).

### Этап 7. Производительность, доступность, интернационализация
- Lighthouse 95+, a11y, полная i18n, батарея/память.

### Этап 8. Production readiness
- CI/CD, мониторинг, feature flags, документация, security audit, load testing.
